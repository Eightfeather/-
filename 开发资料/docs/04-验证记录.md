## 三、本轮修复的缺陷（均有复现证据）

1. **所有 POST 接口参数错位**：`api-shared.mjs` 把 `(query, body)` 同时传给处理器，POST 处理器实际收到 query → 定位/建 Mod/保存全坏。修：`method === 'GET' ? fn(query) : fn(body)`。
2. **显式 root 被评分压过**：`locate` 把显式路径与配置候选一起按分数排序，沙箱输给真实私服，导致误写真实私服。修：显式路径可接受即优先返回。
3. **禁用态 Mod 打不开**：人格模块只查 `mods/`。修：新增 `resolveModDir`，同时查禁用区。
4. **虚拟资源 404**：`assets.gen.mjs` 键缺 `web/` 前缀。
5. **界面显示字面量 `${...}`**：模板字符串误用单引号。
6. **PowerShell 写入损坏 JS**：here-string 双引号触发 `${}` 插值。

## 23. 积木缩进（时点/循环体）与 Backspace 去缩进（v0.5.10）

### 23.1 模型
- 程序块新增嵌套：`timing` / `loop` 拥有 `body`（数组），与 `if` 的 `body` 同构；`normalizeProgram` 递归校验，`countProgramBlocks` 递归统计。
- 旧工程（扁平 blocks）打开时由 `mbNestFlat` 迁移：时点开新组，其后的循环/效果块依次落入最近的帽子（时点/循环）体内，形成「同一条 modular 代码」的缩进结构。

### 23.2 交互
- 拖放或点选放置：落到画布（root）末尾时，若上一个同级块是时点/循环帽子，则自动塞进该帽子体内（自动缩进）。
- 左键点击任意代码块选中（金线描边）；被选中块的路径记在 `S.mb.sel`。
- 按 Backspace：
  - 有缩进 → 去掉一级缩进（移出所属帽子，放到该帽子之后的同级位置）；
  - 已在最外层 → 直接删除该块。
- 输入框/下拉框聚焦时 Backspace 不拦截。

### 23.3 脚本编译
- 递归编译：帽子先输出 `/TIMING:X(...)/` 或 `/LOOP:Y/`，其 body 内连续的 cons/if 合成一条以 `:` 连接的批处理，嵌套帽子各自成行。

### 23.4 实测（CDP，沙箱 e2e-root）
- 扁平程序 `[timing WhenUse, cons buff, loop EveryEnemy, cons healhp]` 打开后渲染为：根 1 个帽子、帽子体内 2 块（cons + loop）、loop 体内 1 块。
- 选中 loop 体内块按 Backspace → 提升到帽子体内（sel 变为 `0.2`）；再按 → 提升到根（sel `1`）；再按 → 删除（sel 清空）。
- 点选放置：时点落根 → healhp 落画布自动进时点体 → loop 落画布自动进时点体；脚本预览 `/TIMING:WhenUse/\n/healhp(_,_)/\n/LOOP:EveryEnemy/`。
- 全程无控制台报错。

补充修复（同版）：
- 点击空缩进区（`.bk-body`）不再被当成「选中父积木」，可正常把携带中的积木放进该层。
- 新建帽子（时点/循环）尚无 `body` 时，`mbStackAt` 会就地补 `body=[]`，保证能往新帽子里落块。
- 实测：时点 → 循环（自动进时点体）→ 点循环体内空位放 healhp → `loopKids=1`，结构 timing > loop > cons。


## 24. 脚本预览按缩进分块（v0.5.11）

- 规则：**同一层缩进内的积木连成一个 `/.../` 块**（内部用 `:` 连接）；**不同缩进才换行**，并按层级缩进 2 空格显示。
- 时点/循环帽子各自独占一行（引擎要求：`TIMING:`、`LOOP:` 必须是独立段，不能与效果函数拼在同一段，否则 `SetupModular` 取不到时点名）。
- 递归编译 `emit(list, depth)`：帽子输出本层行后，body 以 `depth+1` 递归；同层连续的 cons/if 累积到 batch，flush 时按 `':'` 合并。
- 修掉 `normalizeProgram` 的 `loop` 分支丢弃 `body` 的问题（保存后循环体变空）。
- 实测（沙箱）：结构 timing > [healhp, loop[healhp]] 输出
  `/TIMING:WhenUse/` → `  /healhp(Self,5)/` → `  /LOOP:EveryEnemy/` → `    /healhp(Target,1)/`；
  同层两个效果（healhp + gainshield）合并为 `/healhp(Self,5):gainshield(Self,3)/`。

## 26. 循环体只允许放循环块（v0.5.13）

- 规则：任何位于循环体内的位置（含多层嵌套循环）只接受 `loop` 积木；放入其他积木时提示「循环里只能放循环块」，数据不变。

## 39. 零参命令补齐（v0.5.26）

### 39.1 起因

用户反馈 `headschance` 没有实参。查引擎 `ConsequenceHeadsChance`：

```csharp
public void ExecuteConsequence(ModularSA modular, string section, string circledSection, string[] circles)
{
    modular.headsChanceAdder = modular.GetNumFromParamString(circledSection);
}
```

它**不读 `circles[i]`，而是把整段括号文本 `circledSection` 交给 `GetNumFromParamString`** —— 属于“1 个参数、但参数不一定按逗号切”的写法。此前的实参推导只扫 `circles[N]`，这类命令因此一直是 0 参。

### 39.2 修正规则

命令类的参数口径分三种：

## 47. v0.6.3：IF 类（IF / IFNOT / CONTINUEIF）与「遍历」改为时点右侧槽

**改动动机**：用户要求 ①把「条件」大类改名 IF，并补 IFNOT / CONTINUEIF；②修 IF 单行头部溢出，逻辑支持 无 / AND / OR / XOR；③时点卡做成 Scratch 帽子形，遍历块改放在时点右侧的横向槽（一个时点最多一个遍历）。

**引擎依据**（`ModularSkillScripts.decompiled.cs`）
- `IF(...)`：按 `,` 切段，第一段若是 `AND/OR/XOR` 则为逻辑符，其余为 `左 运算符 右` 条件，运算符只支持 `< > =`；
- `IFNOT` 与 `IF` 同构，取反；`CONTINUEIF` 与 `STOPIF` 同构：条件不成立时跳过本条脚本后续指令（有 LOOP 时跳到下一个目标）；
- `LOOP:` 是**段级**指令（`SetupModular` 里独立解析），作用于整段脚本，因此放在时点卡右侧、每行最多一个。

**数据模型**
- `timing`：`{ k:'timing', v, face, crit, kw, key, loop:{t:'target',n,c}|null, body:[] }`
- `if/ifnot`：`{ k, logic:'none'|'and'|'or'|'xor', conds:[{left,op,right}], body:[] }`，条件上限 8
- `continueif`：`{ k, logic, conds }`（无 body）
- 旧数据在 `normalizeProgram`（后端）与 `mbMigrateLegacy`（前端）里一次性迁移：旧 `{left,op,right}` → `conds:[…]`；旧 `k:'loop'` 子块 → 并入前一个 `timing.loop`，其 body 合并进 timing.body。

**编译规则**：一行 = `TIMING:x(args)` + 可选 `LOOP:y` + 每个顶层语句各自成一段（`/` 分隔）；IF/IFNOT 与其 body 合成一段（子句用 `:` 连）。
例：`Modular/TIMING:StartBattle/LOOP:EveryEnemy/IF(OR,3>5,1>2)`。

**CDP 实测**（沙箱私服，真实鼠标拖拽 + 点选）
- 遍历卡拖到时点右侧「遍历 无」槽 → 槽变实心并显示「所有敌方」，program 写入 `loop:{t:'target',n:'EveryEnemy',c:null}`；
- 条件槽点开就地输入 3 / 5 → `conds:[{left:3,op:'>',right:5}]`；
- 逻辑改 OR → 出现「＋ 条件」→ 第二条条件填 1 / 2 → 预览 `Modular/TIMING:StartBattle/LOOP:EveryEnemy/IF(OR,3>5,1>2)`；
- 保存后 `GET /api/module` 回读一致，`blockCount = 2`。

**已知取舍**
- 默认逻辑为「无」时只有一条条件，不显示「＋ 条件」（因为引擎单条件不带逻辑符）；
- XOR 引擎实现特殊（2 条条件时只看第 2 条；≥3 条要求后续与第 2 条一致），UI 提示照实写，不宣称「恰好一个成立」；
- `STOPIF` 与 LUA 按用户要求暂不做。

| 技能硬币 | `coinList[i] = { operatorType(sign→SUB/ADD), scale(变动值), color, abilityScriptList }` | 积木硬币区；红币补 `SuperCoin`、绿币补 `ExtractCoin`、紫币 `PURPLE`，普通色不改原值 |

| Buff | `buffClass / buffType / canBeDespelled / maxStack / maxTurn / iconId`、`list[].ability` | Buff 基础信息 + 模块行 |

- 一律走 `writeFilesTransactional`（临时→备份→原子替换→失败回滚），随后 `write*Meta(touch)`。
- **防清空护栏**：引用的模块全部不存在时抛 `SafetyError` 中止写入（实测过：缺模块会把技能 `abilityScriptList` 清成 0 条）。

### 51.3 手改锁定语义
- 在「查看输出代码」页把某行改成手改后，该行对应的**整个时点块（含子块）锁定**：视觉灰化 + 虚线 + 🔒，内部控件 `pointer-events:none`，`mbInsert` 拒绝往里插入，只允许整块移动/删除。
- 不做「放弃手改恢复生成」；手改确认弹窗写明后果并可勾选「本次打开编辑器内不再提示」（仅本次会话有效）。
