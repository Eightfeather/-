## 时点中名的两条来源（`src/knowledge/timings.mjs`）

1. `src="game"`（13 条）：`skillTagList.json` 里游戏自带的显示名，如 `WhenUse=使用时`、`OnSucceedAttack=命中时`、`EndCoin=当前硬币攻击后`。
2. `src="tutorial"`（12 条）：Modular 中文教程里的可读名，如 `DuelClash=拼点计数`、`FakePower=预测阶段`、`WhenHit=被命中前`、`OnStartBehaviour=使用时`、`AfterSlots=回合开始`。
3. 其余 **61 条留空**：教程把它们标成「非原生」（游戏没有显示名，如 `OnDie`、`OnBreak`、`Immortal`）或教程没有收录。前端回退显示英文 id。

> 82 条时点里有中文名的共 25 条；教程里出现「非原生」不代表不可用——它是引擎真实时点，只是游戏没有对应的中文显示标签。

## 显示时点 vs 引擎时点

同一批名字有两层含义，不能混用：

- `[命中时]`（`OnSucceedAttack`）：既是引擎时点，也是描述段落 → 可写 `TIMING:OnSucceedAttack`。
- `[正面命中时]`（`OnSucceedAttackHead`）、`[击杀敌方时]`（`EnemyKill`）、`[重复使用 - 正面命中时]`（`ReUseOnSucceedAttackHead`）：**只在描述里分段**，属于游戏的显示变体；实测 MOD 脚本里 `TIMING:` 只用到 24 个名字（OSA、WhenUse、ChangeMotion、OnSucceedAttack、EndSkill…），没有这些子时点。

描述校验对两类都放行，但高亮/统计里 `timing` 计数包含子时点（`tokens[].sub === true`）。

## 转换规则（`toGameText`）

1. 若方括号内已是已知 id（引擎时点名、显示时点 id、标签 id、buff id、关键词 id）→ 原样保留；
2. 若是中文名 → 换成对应 id；**同名冲突时引擎时点优先**（`[使用时]` → `WhenUse`，不会变成 `WhenUse_Force` 或 `OnStartBehaviour`）；
3. 其余原样保留（保存前会被判为「未识别」并弹风险保存）。

## 重新生成

```bat
node 数据缓存\gen-timings.mjs      :: 从 engine_timingDict.csv + skillTagList.json + Modular教程.html 重建 timings.mjs
node 数据缓存\verify2.mjs          :: 回放 707 个真实词条，检查统计与未识别
```
