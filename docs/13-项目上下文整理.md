## 0. 一句话

一个**单文件 Windows 桌面应用**：面向 Lethe（Limbus Company 私服）的 Mod 制作与人格/技能/被动/Buff 编辑工具，核心能力是把「积木式脚本」编译成游戏可执行的 Modular 脚本，并**直接写回 mod 目录里的游戏 JSON**。

## 4. 数据契约（Lethe / Limbus）

### 4.1 mod 目录

```
mods/<Mod名>/
  custom_limbus_data/{personality,skill,passive,buff,personality-passive}/*.json
  custom_limbus_locale/EN/{personalityList,skillList,passiveList,buffList,keywordList}/*.json
  custom_sprites/*.png|webp（profile_<id> / cg_<id> / skill_<id> / buffIcon_<id>）
  custom_buffs/*.txt（0 字节，注册关键词）
  custom_appearance/*.bundle（自定义外观，体积可达 100+ MB）
```

### 4.2 实体包装

- 数据文件是 **`{ "list": [ … ] }`**，**文件名与 id 无关**（一个文件可装多个实体）。
- 写入必须**回到原文件、原位置**替换实体，不能新建文件（否则游戏加载到重复实体）。

### 4.3 本地化

- 目录名复数：`personalityList` / `skillList` / `passiveList` / `bufList` / `keywordList`；`localeCategory()` 会去掉 `List`，注意 buff 的两态 `buf`/`buff`。
- 内容是 **`{ "<id>": { … } }`** 映射；技能是 `levelList[]`，每级有 `name/desc/coinlist[].coindescs[]`。

### 4.4 id 规则

- **不能硬编码公式**：实测 `40004000 → 400040010/020/…`（×1000+序号）、`10824 → 1082401`（×100+1）、敌方技能 10 位（`9029021501`）。
- 校验用「引用关系 + 全库查重」，不用推导公式；越界 INT32 会导致技能文字不显示。

### 4.5 Buff 四件套（缺一不显示）

1. 实体（`custom_limbus_data/buff/*.json`）
2. 0 字节关键词 txt（`custom_buffs/<Keyword>.txt`）
3. locale：`bufList` + `keywordList` 两条
4. 图标：`custom_sprites/buffIcon_<id>.png`（原版图标未解包，暂用首字色块）

## 5. 积木（program）模型

```js
module.program = {
  version: 1,
  blocks: [ // 根层只允许 timing（引擎里没有 TIMING 的段不会执行）
    { k:'timing', v:'WhenUse', face:'Head'|null, crit:'Crit'|null, kw:'', key:'',
      loop: { t:'target', n:'EveryEnemy', c:null } | null,
      body: [ stmt… ] },
    …
  ],
  manual: { "0": "Modular/TIMING:WhenUse/healhp(Self,9)" } // 手改行，key = 根块下标
}
stmt = { k:'cons', n:'buff', a:[value…] }
     | { k:'assign', var:'VALUE_0', val:value }
     | { k:'if'|'ifnot', logic:'none|and|or|xor', conds:[{left,op,right}], body:[stmt…] }
     | { k:'continueif', logic, conds }
value = { t:'target', n, c } | { t:'var', n:'VALUE_0' } | { t:'n', v } | { t:'s', v }
      | { t:'acq', n:'getbuff', a:[value…] } | { t:'math', first, tail:[{op,val}] }
```

### 5.1 编译规则（引擎实证）

- `SetupModular` 按 `/` 切段；`TIMING:` 段只解析时点名；`LOOP:` 段只设模块级字段；其余进 `batch_list`，段内按 `:` 拆指令。
- ⇒ **一行 = 一个时点**：`Modular/TIMING:WhenUse/LOOP:EveryEnemy/buff(Self,Combustion,2)/IF(VALUE_0>3):healhp(Self,2)`。
- 多个时点必须**多行**（用一个模块塞多个时点会互相覆盖，UI 有警告）。
- 内嵌获取函数必须写成 `Gname{a-b-c}`（教程规定），如 `healhp(Self,Ggethp{Self-normal})`。
- `IF` 首段可为 `AND/OR/XOR`，运算符只 `< > =`；**XOR 引擎行为异常**（2 条件只看第 2 条），UI 已提示，不建议用。
- 目标选择器是「基础名 + 连写标签 + 数量 + `$Keyword`」，如 `EveryCoreEnemyNoAbnosExceptSelf3$Combustion`；`+` 表示并集。

## 6. 落地层（v0.7.0 新增，`src/lethe/apply.mjs`）

| 目标 | 写入 | 来源 |
| --- | --- | --- |
| 技能 | `skillData[0].{defaultValue,targetNum,atkType,attributeType}`、`abilityScriptList`、`coinList[]` | 技能基础信息 + 积木硬币区 |
| 硬币 | `operatorType`（正负→ADD/SUB）、`scale`（变动值）、`color`；红币补 `SuperCoin`、绿币补 `ExtractCoin`、普通色**不改**原色 | 同上 |
| 被动 | `attributeStockCondition`/`attributeResonanceCondition` + `requireIDList` | 被动基础信息 + 模块行 |
| Buff | `buffClass/buffType/canBeDespelled/maxStack/maxTurn/iconId` + `list[].ability` | Buff 基础信息 + 模块行 |
| 本地化 | `levelList[].name/desc`、`coinlist[].coindescs[].desc` | 描述区（中文关键词自动转英文 id） |

- 全部走 `writeFilesTransactional`：临时文件 → 备份到 `LCW/journal/rollback` → 原子替换 → 失败回滚。
- **防清空护栏**：引用的模块全部不存在时抛 `SafetyError` 中止（曾实际把技能脚本清成 0 条）。
- 手改行（`program.manual`）优先于编译器生成结果；对应时点块在画布上被锁定（灰化 + 🔒 + 内部不可编辑，只能整块移动/删除）。

## 8. 安全与写盘

1. 名称白名单 + 路径越界拒绝（`..`、盘符、保留名、超长）。
2. 拒绝符号链接/junction。
3. 体积上限（单文件 32 MiB / 请求 64 MiB）。
4. 事务写盘（临时 → 备份 → 原子替换 → 回滚），备份轮转。
5. 本地 API 令牌（页面注入 + `<img>` 走 `?t=`），Host/Origin 校验，非 GET 需 `application/json`。
6. 破坏性操作要求显式确认（删除 Mod 需 `confirm:'DELETE'`）。

## 11. 工程与构建

```powershell
cd E:\辅助文件\Mod编辑器\编辑器正式稿\开发资料
node tools/build-server.mjs     # 内联 web/ + data/ → SEA → dist/server/LetheWorkbenchServer.exe
node tools/build-app.mjs        # gzip 后端 + WebView2 DLL → dotnet build host → dist/app/*.exe，并复制到项目根
```

- **构建前必须** `Stop-Process TheLetheWorkbench,TheLetheWorkbenchServer`（否则复制 EBUSY）。

## 12. 关键决策与理由

| 决策 | 理由 |
| --- | --- |
| 不走 Tauri | 本机无 cargo/rustc，且用户要单文件 exe 不走网页 |
| 零依赖 Node 后端 | 可读可改、无供应链、便于 AI 维护 |
| WinForms + WebView2 壳 | 体积 36 MB，系统自带 .NET 4.8 与 WebView2 运行时 |
| 事务写盘 + 备份 | 直接改玩家 mod，任何半写都会坏档 |
| 撤销只在文件内、保存清栈 | 跨文件撤销会与游戏文件产生不一致 |
| 30 分钟快照整 Mod 全量 + 硬链接 | 大 Mod 366 MB，整抄会卡；硬链接零拷贝 |
| 模块数据放 `%LOCALAPPDATA%\projects\<指纹>` | 换私服不污染、不随 mod 分发、旧目录自动迁移 |
| 落地层「模块 → 游戏文件」 | 变体唯一更强的能力；没有它编辑器产物无法进游戏 |
| 手改锁定整块 | 手改行与积木状态会分叉，锁块避免静默覆盖 |
| 中文说明严格来自英文原文 | 用户明确要求不得联想编造；缺失就留空 |

## 13. 踩过的坑（教训清单）

1. **PowerShell here-string 写中文** 会产生乱码；改代码一律用 node 脚本 + 绝对路径 + `indexOf/slice`。
2. `String.replace(a, b)` 中 `b` 含 `$'` 会被解释为「匹配点之后的原文」→ 文件被反复插入后缀（曾把 app.js 从 147 KB 撑到 442 KB）。
3. PowerShell 5.1 的 `Set-Content -Encoding utf8` 写 BOM → `JSON.parse` 失败 → 配置被忽略（表现为「配置指向沙箱却连真实私服」）。
4. `meta.mjs` 里混用 CRLF/LF 时，用 `\r\n` 锚点 `replace` 会**静默不命中**。
5. CDP：`Runtime.evaluate` 不能有顶层 `await`；合成 `MouseEvent('click')` 不产生 click；要真鼠标用 `Input.dispatchMouseEvent`。
6. `fetch` 传对象 body 会被序列化成 `"[object Object]"`；必须 `JSON.stringify`。
7. `app.js` 是 ES 模块，内部函数不在 `window`，自动化只能点 UI 或读 `window.__WBS`。
8. HTML5 拖放在 WebView2 里不可靠 → 全部改指针拖拽（mousedown/mousemove/mouseup + `elementFromPoint`）。
9. `.mb-trash` 若 `pointer-events:none` 则 `elementFromPoint` 命中不到 → 用几何判定。
10. 宿主被强杀时会留下孤儿 `server.exe`（曾 27 个 / 799 MB）→ Job Object `KILL_ON_JOB_CLOSE`。
11. 构建复制到项目根时若 app 在运行会 `EBUSY`。
12. `node -e` 在 PowerShell 里引号会被吃掉，复杂脚本一律落文件。
