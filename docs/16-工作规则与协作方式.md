# 16 工作规则与协作方式（长期有效）

> 本文是所有后续工作的约定，位置固定在 `编辑器正式稿\docs\`（源码文档已从 `开发资料\docs` 迁到这里）。

## 一、交付流程（每次改完必做）

1. **只改必要文件**：改前先定位文件与行号，改后给出「文件:行号」清单。
2. **必须自测**：`node --check` → 构建 `tools/build-server.mjs` + `tools/build-app.mjs`（先杀 `TheLetheWorkbench.exe` / `TheLetheWorkbenchServer.exe`，否则复制 EBUSY）。
3. **必须截图/数值自查**：用 WebView2 CDP（`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333`，启动与驱动写在同一次 pwsh 调用里）取 DOM 与几何数据，确认「看到的就是改的」。本会话模型无图像输入，只能用数值与文本证据，需如实说明。
4. **必须重启编辑器**：`Start-Process E:\辅助文件\Mod编辑器\编辑器正式稿\TheLetheWorkbench.exe`，回报版本号与是否定位到私服。
5. **必须写文档**：在 `docs/04-验证记录.md` 追加一节（改动点、实测、边界）。

## 二、提问规则

- 能自己判断的一律执行；**只在拿不准、且猜错会浪费大量返工**时提问。
- 提问要一次问清、给出推荐项，不要连环追问。

## 三、需求处理规则

- 独立新增的工作 → 新增步骤；**之前已有但被删的步骤 → 要重新插入回来**（删过的旧步骤不能丢）。
- 用户逐条反馈按编号归档，逐条回复「改了什么 / 在哪 / 实测」。
- 不擅自扩大范围；设计稿未批准的视觉/交互不自己发挥。

## 四、存储与数据规则

- 设计态数据全部在 `<Lethe>\LCW\`（`projects/`、`backups/`、`journal/`、`logs/`、`state.json`、`session.json`、`README.txt`）。
- 运行态必须在私服侧：禁用 Mod 走 `.lethe-workbench/disabled/`（移动，不删除）。
- `%LOCALAPPDATA%\LetheWorkbench\` 只留无法自举的：`config.json`、`runtime/`、`logs/`、`webview2/`。
- 改 Mod 一律走「临时 → 备份 → 原子替换 → 失败回滚」，禁止非原子直写。

## 五、技术红线（踩过坑的）

- PowerShell here-string / `Set-Content` 写含中文的文件会按 ANSI 读坏 → **用 write 工具或 node 写文件**。
- 拼接代码用 `indexOf` + `slice` 或函数式 `replace(x, () => …)`；**禁止替换串里出现 `$'`**（会展开成“匹配点后的全文”把文件撑爆）。
- `app.js` 是 ES 模块，内部函数不在 `window` 上，CDP 只能点 UI 或读 `window.__WBS`。
- 构建前必须杀进程；单实例 Mutex 会让新 exe 静默退出、CDP 连到旧实例。

## 六、记忆

- 项目内规则以本文为准；跨会话的个人偏好写进 DSH 持久记忆（`memory_write`）。
- 上下文策略：每完成一批即分段压缩，保留「路径 + 函数名 + 实测数字 + 未完成项」。
