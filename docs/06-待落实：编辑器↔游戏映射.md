# 06 · 待落实：编辑器 ↔ 游戏映射

> 状态：**未实现（有意推迟）**。用户在 v0.3 明确要求「先别做编辑器到游戏的映射，这是后面落实时会搞的，在这一块留一个给后面返工的介绍就行」。
> 本文就是那个「返工入口」：记录当前编辑器的数据形态、将来要映射到游戏文件的哪些位置、以及代码里该动哪几个函数。

---

## 1. 现在是什么样（v0.3）

技能编辑当前只读写**编辑器自己的草稿**，一个技能两份文件，都在 Lethe 根下：

```
<letheRoot>/.lethe-workbench/meta/skills/<Mod名>/
  <技能id>.json        # 基础信息 info + 描述 description + updatedAt（参与撤销/重做）
  <技能id>.code.json   # 代码区 code = { skill: [模块id...], coins: [{color, value, modules:[...]}] }（不参与撤销）
```

- 基础信息 `info`：`{ basePower, coinCount, atkCorrection, targetNum, physical, sin, sign }`
- 描述 `description`：**纯文本**，关键词用 `[中文名]` 书写（例：`[使用时]使本技能的硬币威力+1，并施加[烧伤]3级`）。
- 代码 `code`：技能置入区放模块 id；硬币区按 `coinCount` 生成，每枚有颜色与变动值。
- 3 个测试模块（`test-burn-quake` / `test-power-gain` / `test-heal-sp`）是**可拖动的占位**，没有映射、也没有实际作用。

**当前「保存」只做一件事**：清空该技能的撤销栈（`POST /api/skill/save` → `session.clear`）。游戏文件（`mods/<Mod>/custom_limbus_data/skill/*.json`、`custom_limbus_locale/EN/skillList/*.json`）**一个字节都不会被改**。

## 2. 将来要映射到哪里

游戏侧的目标文件（实测 D:\私服）：

```
mods/<Mod名>/custom_limbus_data/skill/<任意文件名>.json
  { "list": [ { "id": 2090101, "skillType": "SKILL", "skillTier": 1,
                "skillData": [ { "attributeType": "AZURE", "atkType": "SLASH", "defType": "ATTACK",
                                 "defaultValue": 4, "targetNum": 1, "skillLevelCorrection": 0,
                                 "abilityScriptList": [ ... ],
                                 "coinList": [ { "operatorType": "ADD", "color": "GOLD",
                                                 "scale": 3, "prob": 0.5,
                                                 "abilityScriptList": [ ... ] } ] } ] } ] }

mods/<Mod名>/custom_limbus_locale/EN/skillList/<任意文件名>.json
  { "<技能id>": { "id": "...", "levelList": [ { "level": 1, "name": "...", "desc": "[WhenUse]...",
                                                "coinlist": [ { "coindescs": [ { "desc": "[OnSucceedAttack]..." } ] } ] } ] } }
```

### 2.1 基础信息 → skillData 字段（一一对应，待确认细节）

| UI 字段 | 游戏字段 | 备注 |
| --- | --- | --- |
| 基础威力 basePower | `skillData[0].defaultValue` | 数字 |
| 硬币数量 coinCount | `coinList.length` | 1–12，改动时同步增删硬币 |
| 攻击修正值 atkCorrection | `skillData[0].skillLevelCorrection` | 数字 |
| 攻击容量 targetNum | `skillData[0].targetNum` | 数字 |
| 物理属性 physical | `skillData[0].atkType` | SLASH/HIT/PENETRATE/NONE |
| 罪孽属性 sin | `skillData[0].attributeType` | CRIMSON/AZURE/SHAMROCK/AMBER/VIOLET/SCARLET/WHITE/NEUTRAL |
| 正负硬币 sign | 影响硬币 `operatorType`（ADD / SUB 或 MUL）与基值 | **映射规则待用户确认** |

### 2.2 硬币 → coinList[i]

| UI 字段 | 游戏字段 |
| --- | --- |
| 硬币顺序 | `coinList` 数组顺序 |
| 硬币颜色 color | `coinList[i].color`（GOLD / 红 / 绿 / 紫 —— 具体枚举名待落实） |
| 硬币变动值 value | `coinList[i].scale`（正负由 `operatorType` 决定） |
| 硬币上的模块 | `coinList[i].abilityScriptList` |
| 硬币概率 | `coinList[i].prob`（编辑器暂无 UI，用默认 0.5） |

### 2.3 模块 → abilityScriptList 条目

模块（`data/modules/<id>.json` 的 `{id, name, desc, test}`）将来要编译成脚本条目：

```json
{ "scriptName": "GiveBuffOnSucceedAttack",
  "buffData": { "buffKeyword": "Combustion", "target": "...", "stack": 1, "turn": 1 },
  "conditionalData": { ... } }
```

- 放置在**技能置入区** → `skillData[0].abilityScriptList`
- 放置在**某枚硬币** → 该硬币的 `abilityScriptList`
- 一句话模块「[使用时]若目标的[烧伤]强度与[震颤]强度之和不低于6级，则使本技能的硬币威力+1」在引擎侧是 `Modular/TIMING:WhenUse/...` 形式（参考 `D:\私服\dsh_AI\docs\LimbusCompanyMod_知识库.md` 与 ModularSkillScripts 的 DSL）。

### 2.4 描述 → 游戏描述文本

- 编辑器里写中文关键词 `[烧伤]`，游戏里必须是英文 id `[Combustion]`（时点同理：`[使用时]` → `[WhenUse]`）。
- 现有函数：`src/lethe/keywords.mjs` 的 `analyzeDescription()` / `toGameText()`（已实现，返回 `game` 预览）。
- 写盘时：把 `toGameText()` 的结果写进 locale 的 `desc`，并按 `[Tag]` 段落切分到 `coinlist[].coindescs[]`（注意游戏描述是「技能段 + 每枚硬币段」，与编辑器的一段纯文本需要拆分策略）。
- 未识别关键词：保存时弹「有错误的关键词输入，请检查拼写」，用户「无视风险保存」→ 原样保留、不做翻译。

### 2.5 v0.4 新增的三块（模块 / 被动 / Buff）

v0.4 把「模块」正式做成编辑器内的实体，并新增被动、Buff 两个编辑器。它们的映射同样全部推迟：

| 层的存储 | 位置 | 是否进游戏 |
| --- | --- | --- |
| 模块库 | `<letheRoot>/.lethe-workbench/meta/modules/<id>.json`（`{id,name,desc,prefix,kind,test}`） | ❌ 只存编辑器 |
| 被动草稿 | `meta/passives/<Mod>/<id>.json`（`{info,code,description,updatedAt}`） | ❌ |
| Buff 草稿 | `meta/buffs/<Mod>/<id>.json` | ❌ |
| 被动 / Buff 实体 | `custom_limbus_data/{passive,buff}/…`、`custom_limbus_locale/EN/{passiveList,bufList}/…`、`custom_buffs/<关键词>.txt` | ✅ 创建时即写入（空壳） |

将来要补的映射：

- **被动**：`info.needCondition + sin + conditionType('have'|'resonance') + count` → 实体的 `attributeResonanceCondition: [{ type, value }]`；`conditionType` 的两种语义在引擎侧是否对应不同字段，**待确认**。`code.modules[]` → 实体的 `requireIDList`（目前原版里放的就是 `Modular/TIMING:…` 脚本）。
- **Buff**：`info.buffClass / buffType / canBeDespelled / maxStack / maxTurn / iconId / special` → 实体同名字段（创建时已同步一部分，编辑时要同步）；`code.modules[]` → 实体的 `list[].abilityScriptList`；`special`（是否为「特殊某 buff」）的落点待确认；图标仍缺上传 UI（目标文件 `custom_sprites/buffIcon_<iconId>.png`）。
- **模块**：`prefix`（时点）与 `desc` 里的 `[关键词]` 一起编译成 `Modular/TIMING:<prefix>/…` 片段；同一个模块放进「技能置入区」与「硬币置入区」时输出是否不同，**待确认**。

## 3. 代码里该动哪里（返工清单）

1. `src/lethe/meta.mjs`：新增 `compileSkill(letheRoot, mod, id)` → 读 meta 的 info/code/description，产出 `{entityFiles, localeFiles}`（纯数据，不落盘）。
2. `src/lethe/skills.mjs`：新增 `writeCompiledSkill(...)`，用 `writeFilesTransactional` 原子写入 `custom_limbus_data/skill/` 与 `custom_limbus_locale/EN/skillList/`；已存在的技能按原文件原位置替换实体（不要新建重复文件）。
3. `src/server/api.mjs`：`POST /api/skill/save` 从「清空撤销栈」改为「编译 → 校验 → 事务写入 → 记录撤销 → 清栈」；新增 `GET /api/skill/compile-preview`（导出前预览 diff）。
4. `src/web/app.js`：`commitSkill()` 增加「编译失败/警告」展示；描述拆分策略的 UI 提示。
5. `src/lethe/validate.mjs`：技能校验（id 32 位、硬币数 1–12、颜色枚举、脚本名白名单）。

## 4. 已知约束（不要忘）

- 导入的原版技能**保持原 id**，等于覆盖原版；保存前必须二次确认。
- 大文件（bundle/exe/zip）不要碰，也不要整目录复制（见 docs/03 的硬链接方案）。
- 描述里的 `[]`：时点表与 buff 表**不重合**，解析时不做优先级，只是分表查找。
- 一切写盘必须走 `writeFilesTransactional`（原子 + 回滚），不要直接 `fs.writeFile`。
